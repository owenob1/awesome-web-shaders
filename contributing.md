# Contribution Guidelines

Thanks for taking the time to contribute! Please make sure your suggestion is a genuinely awesome web-shader resource before opening a pull request.

## Adding to the list

Please ensure your pull request adheres to the following guidelines:

- Search previous suggestions and the existing list before making a new one, to avoid duplicates.
- Make sure the resource is **relevant to web shaders** — GLSL, WGSL, WebGL, WebGPU, or the libraries, tools, and learning material around them.
- Prefer resources that are **high quality, actively maintained, and widely respected**. A new or niche resource should be genuinely excellent to earn a spot.
- Add one link per pull request when possible, and add it to the bottom of the appropriate category.
- Use the following format: `- [Name](link) - Description.`
- The description should be clear, concise, and start with a capital letter and end with a period.
- Keep descriptions short — ideally under ~20 words. Don't editorialize or use marketing language.
- Link the resource's canonical homepage or repository, not a mirror or aggregator.
- New categories, or improvements to the existing categorization, are welcome.
- Check your spelling and grammar.
- Make sure your text editor is set to remove trailing whitespace.
- The pull request title and commit message should be meaningful (e.g. "Add Lygia to Shader Utilities"), not "Update readme.md".

## Quality standards

To be included, a resource should meet **most** of these bars:

- It teaches, enables, or demonstrates writing shaders on the web.
- It is either a recognized standard, actively maintained, or represents notable recent work.
- Documentation or examples make it approachable.
- Link targets are stable and freely accessible (paid courses are allowed if clearly among the best in their category).

## Updating your pull request

If a maintainer asks for changes, please edit your existing pull request rather than opening a new one. If you're unsure how, [here is a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md).

Thank you for your suggestions!
